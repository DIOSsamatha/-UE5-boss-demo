## 编译修复：C2065 + 警告清零
- **`C2065 'bUseControllerDesiredRotation': 未声明的标识符`**
  - 根因：我把 `bUseControllerDesiredRotation` 当成了 Character/APawn 的属性，写成了 `this->bUseControllerDesiredRotation`。
  - **它其实是 `UCharacterMovementComponent` 上的属性**（`CharacterMovementComponent.h:438`），必须写 `GetCharacterMovement()->bUseControllerDesiredRotation = true;`。
  - 引擎注释明确：该属性**会被 `bOrientRotationToMovement` 覆盖**，所以横移模式必须 `bOrientRotationToMovement = false`，两者在同一组件上一起设。
- 最终横移朝向代码（FightPlayerCharacter 构造函数）：
  ```cpp
  bUseControllerRotationYaw = false;
  if (UCharacterMovementComponent* MoveComp = GetCharacterMovement())
  {
      MoveComp->bUseControllerDesiredRotation = true;  // 属性在 MovementComponent 上！
      MoveComp->bOrientRotationToMovement = false;
      MoveComp->RotationRate = FRotator(0.f, 720.f, 0.f);
  }
  ```

## 重大修正：root-motion 混合空间"跑完拉回"根因
- **之前错误结论**："ABP 默认 Root Motion Mode=From Montages Only，混合空间里的 root motion 不生效、等效原地播"。**这是错的。**
- **真相**（引擎 `AnimSequence.cpp:1824-1843` + `AnimCompressionTypes.h:878-886`）：
  - 该模式只决定"是否提取 root motion 来驱动位移"，**但动画里的根骨位移照样播出来**。
  - root-motion 的 Walk/Run 在混合空间里每轮根骨前移一段、结尾瞬间跳回原点 → 表现"跑完拉回、不一直往前" + 整体不自然。
- **正确修法（原地 in-place）**：每个 Walk/Run 动画 Details → Root Motion 分类：
  - `Root Motion Root Lock = Zero`
  - `Force Root Lock = true`（bForceRootLock 的用途就是"即使不启用 root motion 也强制锁根骨"）
  - 根骨每帧钉死原点 → 循环无缝、不再拉回，位移仍由输入驱动。
- **一键脚本**：`Tools/FixLocomotionRootMotion.py`（编辑器 Output Log 切 Python 粘贴运行；按 Walk/Run 名过滤 Root-Motion 目录下 AnimSequence，批量设上述两属性并 save）。**不用重编、不用重启。**
- 脚底打滑 = WalkSpeed/RunSpeed 与动画自身 root-motion 速度不一致（或这步没做）→ 先做 Root Lock=Zero，再微调速度匹配。
- 另：Idle 在 `In-Place/`、Walk/Run 只在 `Root-Motion/`（无 in-place 版本，故必须靠 ForceRootLock 解决，不能靠换资产）。
