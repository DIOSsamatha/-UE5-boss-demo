**新增脚本 `Tools/AddBossWeaponSockets.py` 自动补插槽**（编辑器里跑，不用编译、不用重启）。
关键难点与解法（**SocketName/BoneName 是 `VisibleAnywhere`，Python 只读**）：
1. `unreal.new_object(unreal.SkeletalMeshSocket, mesh)` 造对象（`new_object(type, outer, name, base_type)`）
2. `mesh.add_socket(sock, False)` —— SocketName 为空时引擎自动命名 `SocketN`、父骨骼=根骨骼
   （⚠ `AddSocket` 要求 `GetOuter()==mesh`；`BoneName` 若**非空但不存在**会直接 return 不添加）
3. `sock.set_socket_parent(mesh, bone)` 用**公开接口**改父骨骼（会校验骨骼存在）
4. `unreal.SkeletalMeshEditorSubsystem.rename_socket(mesh, auto, 目标名)` 改 SocketName
   （引擎里唯一能写 SocketName 的公开接口 —— `SocketName` 属性本身写不了）
5. `sock.set_socket_local_transform(Transform)` 调局部位移/旋转
派生出的**通用套路**：遇到 `VisibleAnywhere` 只读属性，先找引擎有没有对应的
`UFUNCTION(BlueprintCallable)` setter，没有就走"先创建 → 用公开接口改名/改父"绕过去。

Khaimera 骨架是**标准 UE4 Mannequin 命名**（`hand_r` / `middle_03_r` / `index_03_r`…），
且自带 `weapon_r` / `weapon_l` 骨骼。默认取 `hand_r → middle_03_r`（手心→中指尖=爪刃）。

## KhaimeraPlayerCharacter 编译失败的根因（已定案）

`Reset Orientation and Position` 节点调用的 `ResetOrientationAndPosition` 属于
**`HeadMountedDisplayFunctionLibrary`（在 `XRBase` 插件里）**，而本工程 `.uproject` 的
Plugins 只有 `ModelingToolsEditorMode` / `GameplayAbilities` / `GameplayTagsEditor`
—— **XRBase 没启用**（引擎里 `Engine/Plugins/Runtime/XRBase/XRBase.uplugin`，
`EnabledByDefault: False`）→ 函数找不到 → 蓝图编译失败。

影响面：该蓝图只被**它自己**和 `Khaimera_AnimBlueprint`（预览）引用，
`BP_Boss` / `BP_FightPlayer` / `BP_FightGameMode` 均 0 引用。
→ PIE 无影响；但 **Cook/打包时蓝图编译失败会报错**，上线前要处理。
修法优先级：删节点(30s，推荐) > 删资产 > 启用 XRBase（会白白带进 VR 模块）。

## ★★ 修正：BOSS 攻击不播的真正根因 + 最终修法（同日后续，已编译通过）

用户复报"锁定视角攻击时镜头还是乱摇"+"boss 攻击动作没实现"。排查后前一版（单节点+序列待机）
其实是**错的假设**：单节点实例只在 `SetAnimationAsset` 的是【蒙太奇】时才注册该蒙太奇自带的 Slot 节点，
之前用"序列"当待机（序列无 Slot）→ `DefaultSlot` 永远不存在 → GAS 攻击/受击/破防/死亡 `Montage_Play`
**静默失败**（找不到 Slot）→ BOSS 攻击不动。玩家能动只因玩家有真 ABP 带 DefaultSlot。

**最终修法（C++ 单节点，零手动 ABP / 零 Python）**，改 `BossCharacterBase.cpp/.h`：
- `SetupBossAnimation()`：单节点模式下，把 `Idle_Relaxed_A`/`Jog_Fwd` 用
  `UAnimMontage::CreateSlotAnimationAsDynamicMontage(序列, "DefaultSlot", 0.25,0.25,1.f,/*LoopCount*/0)`
  包成【挂在 DefaultSlot 的循环动态蒙太奇】，再 `PlayAnimation(待机蒙太奇, true)`。
  单节点 `SetAnimationAsset(蒙太奇)` 会注册 `DefaultSlot` 节点 → 攻击蒙太奇就能分层播出来。
- `UpdateBossLocomotion()`：按速度在 待机/行走 动态蒙太奇间切换；判定"战斗蒙太奇在播"用
  `IsAnyMontagePlaying() && !Montage_IsPlaying(CurrentLocoMontage)`，结束（StopAllMontages 把待机停掉）后自动恢复待机。
- `BossAnimBlueprint` 属性保留为**可选** ABP 覆盖，但**不再自动按路径 Load**（防瑕疵 ABP 反而继续失败）。
- 头文件新增 `BossIdleMontage`/`BossJogMontage`/`CurrentLocoMontage`（TObjectPtr<UAnimMontage>）。

**锁定镜头乱摇（攻击 BOSS 时）两个根因都修了**：
1. `LockOnComponent::TickComponent` 出招（`State_Attacking`）时跳过强制拧身体（与招式根运动互殴→身体甩动→相机抖）。
2. `FightPlayerCharacter::UpdateLockOnCamera` 锁定期间 `CameraBoom->bDoCollisionTest = (Target==nullptr)` 关掉。
   出招突进贴脸时臂长线戳进 BOSS 胶囊/场景，碰撞把相机往回顶→狂抖。

**构建**：关编辑器后 `python Tools/run_build.py` → exit 0（2 分 4 秒）。DLL 已落到 demoEditor。
**验证点**：进游戏锁定 BOSS 后普攻/技能 → 镜头平滑不抖；BOSS 挥砍/弹幕/突进/大招 + 四向受击/破防/死亡动画均应分层正常。
日志关键字：`[Boss][动画] 单节点兜底 + 待机循环蒙太奇 ... DefaultSlot 已注册，攻击蒙太奇可正常分层`。
