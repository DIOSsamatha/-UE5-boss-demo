## 诊断：PIE 里"控制不了角色"（角色已可见）

**现象**：PIE 大纲里已是 `BP_FightPlayer0`（默认 Pawn 类修好了，角色可见、能播 ABP），但所有按键无反应。

**根因（已由二进制扫描证实）**：`BP_FightPlayer` 的 **8 个 InputAction 槽位一个都没填**（只引用了 `IMC_FightPlayer`）。
`AFightPlayerCharacter::SetupPlayerInputComponent` 里每个绑定都是 `if (MoveAction) { BindAction(...) }`，
指针为空 → 8 个 `BindAction` 全部跳过 → **一个键都没绑上。不报错、不崩溃、就是没反应**。
（`Config/DefaultInput.ini` 的 `DefaultInputComponentClass` 已正确指向 `EnhancedInputComponent`，排除输入组件类型问题。）

**IMC 精确键位扫描（新技巧）**：`.uasset` 名字表里 FString 按「int32 长度 + 字符 + \0」存（长度含末尾 \0），
所以单字符键名可精确定位为 `02 00 00 00 57 00`（= FName "W"）。
用这个格式匹配后确认 IMC 里真实键名只有 **10 个**：`W A S D E SpaceBar LeftShift LeftMouseButton RightMouseButton Mouse2D`
→ `Q`、`LeftAlt` **不存在** → 8 个 Action 里 **`IA_Defense` 与 `IA_Flash` 只有一个绑了键（E），另一个是空的**（Move 占 4 个键）。
（普通子串匹配会把 Q/R/F/C/V 误判为已绑，因为它们是 `GA_` 这类字符串的子串 —— 必须用精确 FName 匹配。）
另外 IMC 只有 `Pressed` / `Hold` 触发器，**没有 `Down`**。

**代码加固（已改，待重编）**：`Player/FightPlayerCharacter.cpp`
1. 构造函数按 `/Game/FightPlayer/Input/` 约定路径兜底加载 `IMC + 8 个 IA`（`ConstructorHelpers::FObjectFinderOptional`），蓝图未填也能跑
2. `SetupPlayerInputComponent` 收集空槽位并 `UE_LOG(Error)` 列出槽位名（不再静默跳过）

## 左 Shift 双语义：短按闪避 / 长按奔跑

**需求**：左 Shift 短按 = 闪避（UGA_PlayerDodge / Ability_Movement_Dodge），长按 = 奔跑（MaxWalkSpeed 提到 RunSpeed）。

**实现（FightPlayerCharacter.cpp/.h）**：
- `HandleRunStart`（键按下 / Started）：启动 `RunHoldThreshold`（默认 0.25s）计时器，到点才进奔跑（`OnShiftHoldExpired` 把 MaxWalkSpeed=RunSpeed、bShiftRunActive=true）
- `HandleRunEnd`（键松开 / Completed）：若 bShiftRunActive → 停奔跑；否则 → 取消计时器 + 触发闪避
- `OnShiftHoldExpired` 必须声明 `UFUNCTION()`（计时器回调要求）

**关键前提（踩坑）**：`IA_Run` 的 IMC 触发器必须是 **`Down`**。
- `Down` → Started 在按下、Completed 在松开，长短按可区分 ✅
- `Pressed` → Completed 在按下同一帧立即发出，结果变成"每次按 Shift 都闪避、永远跑不起来" ❌
- 扫描确认当前 IMC 只有 `Pressed`/`Hold`，没有 `Down` → 用户需在编辑器把 IA_Run 改成 Down（IA_Defense 同理必须是 Down）。
- `IA_Flash`（Left Alt）仍保留为"纯闪避"备用键，未删除。

**状态**：代码已改完，待重编（编辑器开着导致 Live Coding 锁，build 失败 exit=6）。用户改完 IMC 触发器后需关闭编辑器再编。文档 A5 已补充双语义说明与 Down 触发器警告。

## 移动 / 视角问题（编辑器内修，不重编）

**现象**：A/D 不能左右移动；前后方向怪、不跟镜头；视角转太快；不知道怎么加移动动画。

**根因**：
1. `IA_Move` 在 IMC 里配错了 —— 用了 `SwizzleAxis` / `Negate` 修饰器导致 2D 向量 X/Y 与代码期望错位。代码约定：`Axis.Y=前后(W/S)`、`Axis.X=左右(A/D)`，靠 `Controller->GetControlRotation().Yaw` 算 Forward/Right（即镜头方向）。
2. `IA_Look` 鼠标原始增量没乘灵敏度，直接喂 `AddControllerYawInput` → 太快。

**修复（全在编辑器）**：
- `IA_Move` 类型改 **2D Vector(Axis2D)**；IMC 里删掉旧的，重新加 4 条全部映射到 IA_Move、**不加任何 Modifier**：W=(0,1) S=(0,-1) D=(1,0) A=(-1,0)。Swizzle/Negate 会搅乱轴，必须删。
- `IA_Look` 加 **Input Modifier → Scale**，X=0.15 Y=0.15（代码已做 `-Axis.Y` 俯仰反向，Y 用正值即可）；手感不对调 0.05~0.3。
- 移动动画在 `ABP_FightPlayer`：Event Blueprint Update Animation 里 `TryGetPawnOwner→GetVelocity→VectorLength` 写 `Speed` 变量；AnimGraph 用 BlendSpace1D(Speed) 或状态机(Idle/Run/Jump)，SwordAnimsetPro 有现成 locomotion。攻击/闪避动画由 GA 的 PlayAnimMontage 播，与移动动画两套并存。

**注意**：IA_Move / IA_Look 改完**无需重编**（纯资产）。之前的左Shift 双语义 C++ 改动才需要关编辑器重编。
