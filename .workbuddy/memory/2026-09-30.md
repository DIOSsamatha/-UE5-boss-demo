## 凌晨（00:20）用户报：「还是没有多个招式，而且现在一直在重复一个动作」

### 根因（两个确凿的缺陷，都是代码 bug 不是配置问题）

**根因 1：`AttackIntervalMin/Max` 只被赋值、从来没有人读。**
- `EnsureDefaultPhases` 里写了 `Phase1->AttackIntervalMin = 2.2f / Max = 3.4f`，
  但全工程 grep **没有任何读取点** → BOSS 打完一招只等招式自己的后摇（Slash_01 仅 0.55s）就立刻再打。
- 后果：出招周期 ≈2s，而各招 CD 是 Slash_01=2.2s / Slash_02=3.0s / Heavy=6~9s / Charge=6s / Pounce=5s
  → **长 CD 的招永远在冷却里**，能用的只剩 CD 最短、权重又最高（3.0）的 Slash_01
  → 画面上就是"一直在重复同一个挥砍"。
- 修：`SetState(Chase)` 时掷一次间隔，`UpdateChase` 开头守门（间隔里继续追近/后撤，别站着发呆）。

**根因 2：固定背板被重复冷却打乱 + 游标会冻结。**
- 背板取招走的是 `CanUseAttack(...)`，里面查 `AttackCooldowns` → 长 CD 的招在背板里被跳过，
  背板退化成随机兜底 → 又回到根因 1 的"只出 Slash_01"。
- 更糟：原来 `SkipLimit(=3)` 内找不到可用招时**游标不推进** → 永远卡在同一拍 → 每次都掉随机兜底。
  这是典型的"卡死型 bug"：画面上看不出原因。
- 修：① `CanUseAttack` 加 `bIgnoreCooldown` 参数，背板取招传 **true**
  （固定背板的顺序是设计出来的，冷却是随机选招时代的机制，不该插手）；
  ② 背板改成遍历整轮（PatternCount 而不是 SkipLimit），整轮不可用就 **游标 +1** 防冻结；
  ③ 随机兜底排除 `LastAttackName`，避免连着放同一招。

### ★ 真凶 A：位移动画每帧被重播（"移动动画不显示 / 一直重复一个动作"的真正原因）
- 证据：一次 75 秒无头跑，`[Boss][动画]` 切换日志刷了 **66772 条**（≈每帧一次）。
- 根因：`UpdateBossLocomotion` 用 `Montage_IsPlaying(CurrentLocoMontage)` 判"是不是已经在播"，
  但**单节点模式 `PlayAnimation(蒙太奇)` 只是把它设成单节点的 `CurrentAsset`，并不产生 GAS 蒙太奇实例**
  → `Montage_IsPlaying` 恒 false → 每帧都被判成"没在播" → 每帧 `PlayAnimation()` 从头播
  → 动画永远停在第 0 帧。
- 更狠的副作用：每次 `PlayAnimation` 走 `SetAnimationAsset` → `ReinitializeSlotNodes()`
  **每帧重置槽位节点，把刚 `Montage_Play` 的攻击蒙太奇一起冲掉** → 招式根本看不见。
- 修：判据换成"直接问单节点"——`SingleNode->GetAnimationAsset() == Desired`。
  另加迟滞（进 Jog 阈值 50 / 退 Jog 25）+ 最短驻留 0.4s，防止速度抖动引发翻面。
- 效果：切换日志 66772 → 10。

### ★ 真凶 B：AI 角色不能用 `AddMovementInput`（我上一轮的兜底是无效的）
- 引擎 `CharacterMovementComponent.cpp:1723`：
  `bShouldPerformControlledCharMove = CharacterOwner->IsLocallyControlled() || ...`
  → **只有"本地控制"的角色才会把输入交给 `ControlledCharacterMove`**。
  BOSS 是 AIController 接管的服务端角色 → 累积的输入每帧在 `TickComponent` 开头被
  `ConsumeInputVector()` 吃掉后**直接丢弃**，速度恒 0。
- 证据：诊断显示 输入=(0.28,0.96,0) / 模式=1(Walking) / 忽略输入=0 / 组件启用=1，但速度=0，
  17 秒只挪动 14cm（那点位移还是攻击根位移带的）。
- 修：改用 AI 专用通道 `MoveComp->RequestDirectMove(Dir * MaxWalkSpeed, bForceMaxSpeed=true)`，
  并在速度仍为 0 时直接写 `MoveComp->Velocity` 兜底。
- 另一个坑：**寻路失败后别再每帧调 `AI->MoveToActor`** —— 反复失败的寻路请求会触发
  `AbortMove → StopActiveMovement()`，把刚下发的 `RequestedVelocity` 清掉。
  用 `bNavPathUnavailable` 记住"这个关卡没导航"，之后一律直驱。
- 效果：BOSS 真的走起来（(-520,-1110) → (-248,-168)，速度 380，切到「行走 Jog」）。

  把 E_Ability_Start、E_Ability_Throw_MSA 误判成非加法 → 直接导致上面这些坑。

  结果：**非加法 159 个 / 加法 52 个**。
- 规律：**Paragon 里 `*_MSA` 后缀的基本都是加法**（MSA = MeshSpaceAdditive），别拿来当招式源。

## 回血道具"酒"系统（本轮新增，构建中）

### 设计
- 道具名"酒"，按 **R 键**（物理键轮询，不依赖 IMC）触发 `UGA_PlayerUseHeal`。
- 单次回 **30% 最大生命**（玩家 2000 → +600）。走 `UGE_HealEffect`（Instant，Health + SetByCaller=`DemoTag::Data_Heal`=MaxHealth×HealPercent），
  因为直接 SetHealth 不触发 `PostGameplayEffectExecute` 的 clamp+OnHealthChanged，血条不会动。
- 开局带 3 瓶（`DemoBalance::HealItemInitialCount/MaxCount`，`FightPlayerCharacter::BeginPlay` 初始化）。
- 满血 → 灰色"生命已满"；空瓶 → 灰色"酒已喝光"；两者都不扣瓶、直接 EndAbility。
- 喝到蒙太奇 `HealApplyRatio`(0.55) 进度点才真正灌下（"酒到嘴边才回血"）。

### 落地的文件
