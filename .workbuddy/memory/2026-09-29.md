## ★★ 根因 1：Khaimera 的 Idle_Relaxed_A 是【加法动画】→ 单节点拒绝 → BOSS 完全没动画

**证据链（查资产字节 + 运行时日志）**
- 运行时日志（`Saved/Logs/demo.log`）每帧刷：
  `LogAnimation: Warning: Setting an additive animation (AnimMontage_0) on an AnimSingleNodeInstance
   (...CharacterMesh0.AnimSingleNodeInstance_0) is not allowed. This will not function correctly in cooked builds!`
- 扫 Khaimera 动画资产字节（`AAT_LocalSpaceBase` / `AAT_None` 判定）得到：
  · `Idle_Relaxed_A` / `Idle` / `Idle_Relaxed_B` / `TravelMode_Idle` = **加法**（AAT_LocalSpaceBase）
  · `Idle_NonAdditive` / `HS_Idle` / `HS_Idle_Relaxed_A` / `Jog_*` / `Melee_*`（非 MSA 版）= **非加法**
- 引擎源码：`UAnimMontage::IsValidAdditive()` = 所有 SlotAnimTrack 的 `AnimTrack.IsAdditive()`；
  `FAnimTrack::IsAdditive()` 取第一段的 `AnimReference->IsValidAdditive()`。
  → **动态待机蒙太奇的"加法性"继承自源序列** ⇒ 用加法序列做待机 → 单节点 `SetAnimationAsset` 直接拒绝
  ⇒ 待机播不出来 ⇒ BOSS 停在参考姿势（用户看到的那团发白影子），**待机 + 走路全没有**。
- 另外因为 `IsAnyMontagePlaying()` 恒 false，`UpdateBossLocomotion` 会**每帧重试**播放 → 每帧刷一条告警。

**修法（`Boss/BossCharacterBase.cpp`，已编译）**
- 新增文件级 helper `IsAdditiveAnim(const UObject*)`：
  **走 `UAnimationAsset` 基类指针调 `IsValidAdditive()`**（`AnimationAsset.h:1205` 是 public virtual）
  —— 比直接依赖 `UAnimSequence`/`UAnimMontage` 派生类的访问权限稳。新增 `#include "Animation/AnimationAsset.h"`。
- `SetupBossAnimation()`：待机改成候选链 `Idle_NonAdditive` → `HS_Idle_Relaxed_A` → `HS_Idle`，
  取第一个**非加法**的；行走 `Jog_Fwd` 也做同样体检（防以后换成加法版静默失效）。
- `UpdateBossLocomotion()`：开头加保险 —— 待机/行走蒙太奇若是加法资源直接 return（防每帧刷告警）。

**通用教训（重要）**：Paragon 等第三方包里 **`Idle_*` 很可能是【加法动画】**（加法是给 AnimBP 叠姿态用的），
拿去当"整身基础姿势"会在单节点实例上被引擎**静默拒绝**。判定 = `UAnimationAsset::IsValidAdditive()`。
选基础/待机动画前**必须先体检**，名字里的 `_NonAdditive` 才是能当整身姿势用的。
