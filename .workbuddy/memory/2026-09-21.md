### 本轮踩到并固化的三个 UMG 深坑（已写进技能 `ue-cpp-umg-hud`）
1. **建树必须在 `UUserWidget::Initialize()` 之后**。BP 子类的控件树是在 `Initialize()` 里
   （`InitializeWidget` → `DuplicateAndInitializeFromWidgetTree`）才装到 `UserWidget->WidgetTree` 上的；
   提前建树会被整个覆盖 → "控件建了但屏幕上什么都没有"。
   → 正确写法：`RebuildWidget()` 里先 `Initialize()`（public 且幂等）再建树。
   → `NativeOnInitialized()` 不行：它只在 `PlayerContext.IsValid()` 时才跑，而 `UWidgetComponent`
     里的控件是 `CreateWidget(World, Class)` 创建的、**没有** PlayerContext。
2. **UMG 的 Tick 不可靠**。`UpdateCanTick()` 只在 `TickFrequency == Auto` 时计算，
   BP 子类取决于编译蓝图时写死的 `bClassRequiresNativeTick`/`bHasScriptImplementedTick`
   → 用"先建空 WBP、后加 C++ 逻辑"的顺序做出来的 WBP 很可能**永远不 tick**。
   → 本项目改为 `UCombatHUDWidget::TickHUD(Dt)` / `UBossHealthBarWidget::TickHUD(Dt)`，
     由 `AFightGameMode::Tick` 驱动（`PrimaryActorTick.bCanEverTick = true`）。
   → 原生（非 BP）控件如 `UDemoStatusBarWidget` 的 `NativeTick` 是安全的（`WidgetBPClass == nullptr` 必 tick）。
   → **别用** `SetDesiredTickFrequency(Always)`：它走不进那个 `if`，`bCanTick` 保持 false，反而关掉 tick。
3. **每帧轮询 + 延迟掉血**：同一数值被反复 `SetPercent` 时不能重置延迟层的停顿计时器，
   否则金色条永远追不上来。要按"值是否真的变了"分支（`IsNearlyEqual` + `bVisualDirty`）。

### ★ "闪了却照样挨打"的根因：闪避从来没有无敌帧
`State.Invincible` 只能由闪避蒙太奇上的 `AnimNotifyState_Invincible` 给，

→ `UGA_PlayerDodge::ActivateAbility` 显式 `ApplyEffectToSelf(UGE_InvincibleEffect)` +
`UGE_PerfectDodgeWindowEffect`，结束时主动移除（不靠时长自然过期，避免被打断后还挂无敌）。

### ★ 另一个硬伤：攻击期间闪避被完全封锁
`UGA_PlayerNormalAttack` / `UGA_PlayerAttackSkill` 的 `BlockAbilitiesWithTag` 里都有
`Ability_Movement_Dodge` → **一旦开始砍，Shift 彻底没反应**。

⚠ 关键 API 区分（这次踩实）：
- `BlockAbilitiesWithTag` = 本技能激活期间，带这些 tag 的技能**不能被激活**
- `CancelAbilitiesWithTag` = 本技能激活时**取消**正在跑的带这些 tag 的技能
只有 Block 没 Cancel → 挥到一半按 Shift，闪避位移出去了但普攻还在后台跑（锁 WASD、占 `State.Attacking`）
→ "闪了但动作没断"。
→ 攻击技能**移除**对 Dodge 的 Block；闪避/弹刀加 `CancelAbilitiesWithTag`。闪避＝随时可用的取消键。

### ① 锁定视角（`Player/LockOnComponent.*` 重写 + `FightPlayerCharacter`）

- **锁定键不走 Enhanced Input，用 `APlayerController::IsInputKeyDown` 自己维护边沿检测。**
  原因：左Shift 那条"兜底通道"已经和 Enhanced Input 抢过按键状态，
  把 `WasInputKeyJustPressed` 用在鼠标中键上行为不稳定（同一帧被两边消费）。
  自己记 `bLockOnKeyHeld` 最稳，而且**不依赖任何 IMC 配置**（不用新建 IA/改映射）。
  键位：`MiddleMouseButton` 切换锁定，`Q`/`E` 换目标（`LockOnKey` / `SwitchTargetLeftKey` / `SwitchTargetRightKey`）。
- `DisableLockOn` 原来会把 `bOrientRotationToMovement` 还原成 true → **破坏横移(strafe)朝向**，
  表现为解锁后角色"永远面向移动方向"、按 A/D 就转身。已修：解锁只还原 `bUseControllerDesiredRotation`，
  不动 `bOrientRotationToMovement`（它本来就该是 false，见 strafe 方案）。
- **镜头分层**（关键）：新增 `RestingArmLength` / `RestingSocketOffset` 记录"无锁定、无冲击"的基准，
  在构造函数里从 `CameraBoom` 读（不是写死 380）。
  之后锁定镜头与 `UpdateCameraPunch` 都从这两个值出发 ——
  以前两边都直接写 `TargetArmLength`，谁后写谁说了算，表现为"弹反一下镜头就偏了再也回不来"。
- 锁定准星：纯 C++ 控件（四个角各一横一竖 = 8 个 `UImage`），
  每帧把目标世界坐标 `ProjectWorldToScreen` 后写 `CanvasPanelSlot` 的绝对像素位置。
  ⚠ 槽位必须 `SetAnchors(FAnchors(0,0,0,0))` + `SetPosition`；
  用比例锚点会被再拉伸一次，位置就飘了。

### ② 跳砸 → 突进斩（全链路替换，不留残骸）

- 删掉 `EBossAttackType::LeapSmash` / `FBossLeapParams` / 抛物线滞空机制 /
  `ABossCharacterBase::ApplyLandingImpact`（球形）/ `OnBossLanded` 的技能订阅，
  换成 `EBossAttackType::ChargeSlash` / `FBossChargeParams` / 匀速突进 + 扇形收尾。
- 招式手感：**蓄势(可弹反) → 匀速突进(拖刀，碰到就吃伤害) → 收尾重斩(前方 ±78°)**。
  两段判定是刻意的：玩家横向闪开第一段、再往侧后方绕开第二段，操作空间比单段大得多。
  `±78°` 而不是整圈 —— 整圈就没法躲了。
- 突进位移用 `UAbilityTask_ApplyRootMotionConstantForce`（`Strength = 距离/时长`），
  蒙太奇根位移缩放设 0（动画位移 + 代码位移同时开会翻倍）。
- `ApplyAreaImpact(Radius, HalfAngleDeg, ...)` 取代球形的 `ApplyLandingImpact`：
  `HalfAngleDeg >= 180` 或 `<= 0` 视为整圈（大招收尾用），否则只打正前方扇区。
- **⚠ 资产侧必须同步**：`Tools/SetupBossMontages.py` 里 `Boss_Leap_*` 三件套已作废，
  新增 `Boss_Charge_Dash_Montage`(←`Attack_Sprint_Anim`) 与
  `Boss_Charge_Impact_Montage`(←`Attack_Combo_03_02_Anim`)，
  并加了 `RETIRED` 列表在每次跑脚本时自动删除旧资产
  （留着不只是碍眼，更容易在 BP 里被误拖到招式槽 → "配了动作却不出招"）。

### ③ 弹道表现（`Combat/DemoTrailComponent.*` 新建）

- **拖尾做成独立组件**（弹幕 / 突进斩 / 未来蓄力特效共用），不写死在弹体里。
- 实现：**一个 `UInstancedStaticMeshComponent` 的 N 个实例**，
  不是 N 个组件 —— 40 发弹幕 × 12 段 = 480 个组件会直接卡死。
  - 按"**前进多少厘米**"采样（`SampleDistance`），不是按帧 →
    300 和 1500 速度下拖尾密度一致
  - 单帧位移 > `MaxSampleSnapDistance` 视为瞬移 → 丢历史，
    否则生成首帧会从上一个位置拉出一条横穿地图的长尾
  - 一帧走好几步会**补齐中间点**，高速下尾巴才不会断成珠链
  - 头大尾小（`TailSizeScale`）+ 头亮尾淡（`TailBrightness`）
- `⚠ SetNumCustomDataFloats(int32)` 必须在 `AddInstance` **之前**调用
  （引擎禁止"有实例时改通道数"）。`NumCustomDataFloats` 是 private，不能直接赋值。
- ⚠ 材质必须有 `MaterialExpressionPerInstanceCustomData3Vector`(DataIndex=0) 节点，
  否则所有残影一样亮（不崩，但尾巴不淡出）。节点确认存在于 5.7：
  `Runtime/Engine/Public/Materials/MaterialExpressionPerInstanceCustomData.h:38`。

### ④ 命中爆点（`Combat/DemoImpactBurst.*` 新建）

三层各管一件事：**中心爆闪**（前 1/3 冲到最大再迅速收，用 pow 不是线性）+
**贴地扩散环**（对齐命中法线）+ **点光一闪**（没有它特效像贴图贴上去的）。
所有"这条弹该没了"的路径都收敛到 `ADemoProjectile::ResolveAndDestroy()`，
避免某个分支漏放爆点（漏了会表现成"弹幕凭空消失"）。

### ⑤ 特效贴图与材质（**程序化生成，不用 AI 出图**）

- `Tools/GenerateBossVFXTextures.py`（**系统 python + pillow/numpy，不在编辑器里跑**）
  → `Tools/VFXSource/*.png`：`T_VFX_Glow` / `T_VFX_Ring` / `T_VFX_Impact` / `T_VFX_Telegraph`
- **为什么不用 AI 出图**：游戏特效贴图本质是「遮罩」，需要精确可控的数学形状 + 干净 alpha。
  AI 给不出干净 alpha、做不出严格对称、不能参数化调宽度，拿来当发光遮罩会边缘发脏、对不齐。
  解析式（高斯 / 环形 / 星芒）算 512² 只要几十毫秒，而且**可以按参数重生成**。
  - Glow：外圈高斯光晕 + 中心过曝小核（拖尾几十个球叠加不能有硬边）
  - Impact：`|cos(4θ)|^8` → 8 道**细**星芒。指数给 3~4 会变成一片扇形光斑，
    八道芒糊在一起 = 只是一坨发光的圆。再补 45° 的 4 道短芒，不然 8 道等长芒很"人工"
  - 边缘要用 `(1 - r^5)` 软圆盘衰减而不是硬裁 `r>1`，否则对角线留可见直角
- `Tools/SetupBossVFX.py`（**编辑器内跑**）：导入 PNG + 建 2 个基础材质 + 4 个材质实例
  - `M_BossSpriteAdd` 加法混合/无光照：`Emissive = Tex.RGB × PerInstanceCustomData(0..2) × Color × Intensity`
    —— 加法是**顺序无关**的，几十发弹幕同屏时半透明排序问题会非常明显，加法直接绕开
  - `M_BossSpriteAlpha` 半透明/无光照：贴地预警圈用
    （加法会让圈下地面变成"更亮的地面"，预警圈要的是"一层危险区域盖在地上"）
  - 导入时 **`srgb = False`** —— 这些是亮度遮罩不是色彩图，开 sRGB 会把中间调推亮、发光边缘发灰
  - 材质图连线用「按实际输出名去试」的辅助函数（`get_material_expression_output_names`），
    TextureSample 的主输出名是 `RGB` 而不是空串，写死会连不上 → 材质全黑
- C++ 全按 `/Game/Boss/VFX/MI_*.MI_*` 约定路径加载，**取不到就优雅降级**：
  弹体核心球退到 `/Engine/BasicShapes/BasicShapeMaterial`（实心亮球，至少看得见），
  拖尾直接不显示（不崩、不影响任何判定）。`UMaterialInstanceDynamic::Create` 前必须判空。

### ⑥ 动画流畅化

- **真凶不是动画本身，是"切换时没有交叉淡入淡出"**：蒙太奇默认 `BlendIn/BlendOut = 0`
  → 上一段瞬间断电、下一段瞬间上电，每次出招/切状态都"啪"地跳一下。
- `Tools/PolishBossAnimations.py`（编辑器内跑，幂等）按"这个动作被什么打断"分四档统一写：
  | 档位 | In/Out | 用在哪 | 为什么 |
  |---|---|---|---|
  | 急停/受击 | 0.04 / 0.10 | 受击、闪避 | 被打断必须立刻反应，混久了等于"延迟吃招" |
  | 攻击起手 | 0.08 / 0.18 | 挥砍、突进、施法 | 起手要快（不然读招时间变长），收招要稳 |
  | 蓄力/循环 | 0.12 / 0.12 | 循环段 | 首尾姿势接近，混长一点更顺 |
  | 死亡/演出 | 0.12 / 0.30 | 死亡、阶段转换 | 演出类戛然而止很廉价 |
  另设 `blend_out_trigger_time`（≥0 = 提前起淡，让淡出在动画结束时刚好归零）+ `enable_auto_blend_out=True`。
  ⚠ `FAlphaBlend` 结构的属性名各版本不一（`blend_time` / `blend_time_seconds`），逐个 try。
- **⚠ Python 字符串里不要出现 ASCII 双引号做中文引号** —— 会让整个脚本语法错误
  （我写 `"显得"粘手""` 直接 SyntaxError）。用「」或去掉引号。
  写完所有 `Tools/*.py` 都用 `ast.parse` 过一遍，别等进编辑器才发现。
- **C++ 侧最明显的一次硬切：`UGA_BossAttackBase::FaceTarget()` 直接 `SetActorRotation`**
  → BOSS 出招瞬间"啪"地拧过去。改成 `ABossCharacterBase::SetFacingTarget(位置, 角速度, 超时)`
  + Tick 里 `FMath::RInterpConstantTo` **恒速**插值。
  - 用恒速而不是 `RInterpTo`：指数衰减在快到位时明显减速，看起来像"犹豫了一下"；
    招式起手的转向要干脆。
  - 有超时兜底：目标高速绕圈时不会无限追着转。
  - 必须放在 `ABossCharacterBase::Tick` 里**早于 ASC 空指针的提前 return**（纯表现不该因 GAS 未就绪而停）。
  - 与 Brain 的 `UpdateTelegraph` 里那段 `RInterpTo` **不冲突**：
    Brain 只在 Telegraph 状态转，技能只在 Attack 状态转，两者时间上不重叠。
