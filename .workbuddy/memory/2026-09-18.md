## 动画"run 拉回 / 不自然"根因与修法
- 症状：跑/走动画播完根骨瞬间跳回起点（不连续往前），整体运动不自然。
- 根因：Walk/Run 是 root-motion 动画；ABP 默认 `RootMotionMode = NoRootMotionExtraction` → 不提取 root motion 但**根骨位移照样播出来**，循环到结尾跳回原点。
- **关键纠正（之前说错了）**：`RootMotionFromMontagesOnly` 对混合空间里的普通动画**仍是 NoRootMotionExtraction 行为（照样拉回）**，不是 in-place 解法。真正让混合空间 in-place 的是 `IgnoreRootMotion`，但那会连攻击 Montage 的 root motion 一起干掉 → 不要全局设。
- 正确修法（只动 locomotion 资产，最安全）：每个 Walk_*/Run_* 动画资产 Details → Root Motion → `RootMotionRootLock = Zero` + `ForceRootLock = true`。`bForceRootLock` 注释即"即使未启用 root motion 也强制锁根骨"。
- 枚举确认（AnimEnums.h）：`ERootMotionRootLock::{RefPose, AnimFirstFrame, Zero}`；`ERootMotionMode::{NoRootMotionExtraction, IgnoreRootMotion, RootMotionFromEverything, RootMotionFromMontagesOnly}`。`AnimInstance.h:433` `ShouldExtractRootMotion()` 仅对 `RootMotionFromEverything`/`IgnoreRootMotion` 为真。
- 一键脚本：`Tools/FixLocomotionRootMotion.py`（编辑器 Output Log 切 Python 粘贴运行），批量设 16 个 locomotion 动画的属性并保存。
- "运动不自然"另一半：锁根骨后原地播，位移靠 WalkSpeed/RunSpeed；脚速不匹配会溜冰 → 把 RunSpeed/WalkSpeed 调到接近动画 root-motion 本征速度（当前 400/700，若打滑往下调 RunSpeed）。

## 攻击/闪避"放不出来"根因（关键坑）
- 症状：左键普攻、左Shift短按闪避都"无反应"（移动/镜头正常，说明输入与Pawn没问题）。
- 根因：`BP_FightPlayer.DefaultAbilities` 引用的是 **C++ 基类** `/Script/demo.GA_PlayerDodge` 等 5 个，而 Montage 被 `SetupCombatMontages.py` 填进了它们的**蓝图子类** `GA_Dodge`/`GA_NormalAttack` 等。
  C++ 基类里 `ComboMontages`/`DirectionalMontages` 是**空数组** → 运行时授予基类 → 激活后 `PlayCurrentCombo`/`PickDodgeMontage` 取到 `Montage=nullptr` → 立即 `EndAbility` → 看不到任何动画。
- 验证：扫描 BP_FightPlayer.uasset 只含 `GA_PlayerDodge` 等基类名，无 `GA_Dodge_C` / `/Game/FightPlayer/Abilities/GA_Dodge` → 确认引用的是基类。
- 修法：把 `DefaultAbilities` 重指向 5 个**蓝图子类**（它们继承 C++ 资产标签、且持有已填的 Montage/Cooldown）。
- 已写 `Tools/RepointDefaultAbilities.py`：加载玩家 CDO `BP_FightPlayer.Default__BP_FightPlayer_C`，把 `default_abilities` 设为 5 个蓝图生成类。编辑器 Output Log 切 Python 跑即可，无需重编/重启。
- RepointDefaultAbilities.py 坑6：**UE5.7 Python 的 `Blueprint` 对象上没有 `generated_class` 属性**（报 Failed to find property 'generated_class' on 'Blueprint'）
  → 正确做法：`unreal.EditorAssetLibrary.load_blueprint_class("/Game/X/GA_Dodge")`，直接返回 BlueprintGeneratedClass，全版本可用。
- **通用规则（务必记住）**：`DefaultAbilities`（以及任何 GA 授予数组）必须填**蓝图子类**而非 C++ 基类；蓝图子类才承载 CDO 上配置的 Montage/Cooldown/Cost。否则出现"技能激活即结束、无表现"。
- `ResolveAbilityByTag` 解析顺序：先看 `Demo|Ability` 显式槽位（NormalAttackAbility 等，当前均空）→ 再扫 `DefaultAbilities` 按 `GetAssetTags()` 匹配标签（标签在 C++ 构造函数 `SetAssetTags` 设，蓝图 CDO 继承）。
- **DirectionalMontages 顺序坑（已纠正）**：`UGA_PlayerDodge::PickDodgeMontage()` 的下标含义是 `0=右(+X) 1=左(-X) 2=后(-Y) 3=前(+Y)`，不是"前/后/左/右"。填错只会方向反、但仍会播；之前 SetupCombatMontages 按 F/B/L/R 填是反的。FixCombatAbilityWiring.py 已按 [R,L,B,F] 顺序填。
- 新增 `Tools/FixCombatAbilityWiring.py`（诊断+修复合一）：建蒙太奇→填 GA 蓝图子类 Combo/DirectionalMontages→同时把 BP_FightPlayer 的 `default_abilities` 与 5 个显式槽位(python名 normal_attack_ability 等)全指到蓝图子类→打印验证。比分开跑两个脚本更稳，避免"脚本没落盘"导致的反复失败。
