## 给 BOSS 战加 BGM（循环播放）

需求：`K:\selfgame\demo\Content\BGM` 里的 `nickpanek-intense-thrash-metal-instrumental-for-boss-battles-255281.mp3`
（3.0MB，时长 98.5s）循环播放。

### 做法：C++ 挂在 GameMode，零配置
- `AFightGameMode::StartBgm()`，在 `BeginPlay` 最开头调用
  （⚠ 必须放最前面：BeginPlay 里"没有 PlayerController 就 return"不能把音乐一起吞掉）
- `USoundBase` 走 `BgmTrack`（`TSoftObjectPtr`，可在 BP_FightGameMode 里换曲子），
  留空则回落到硬编码 `DefaultBgmPath = /Game/BGM/BGM_BossTheme.BGM_BossTheme`
  —— 留兜底路径是因为"C++ 默认值压不过蓝图 CDO 旧值"这个坑
- 三个对外接口：`StartBgm` / `StopBgm` / `SetBgmVolume` + `GetBgmComponent`（都放 **public**）
- 音量默认 0.35（有氛围但压得住打斗音效）
- `CreateSound2D(..., bPersistAcrossLevelTransition=true, bAutoDestroy=false)`：
  默认 `bAutoDestroy=true` 会在播完时销毁组件，循环第二轮就哑

### ★★ UE5.7 音频 API 的三个坑（网上抄的写法会编译不过）
1. **`CreateSound2D` 返回 `UAudioComponent*`（不是 USoundComponent）**；
   且 `UAudioComponent` **没有 `bLooping` 字段**
2. **`USoundComponent`（老的那种）在 5.7 里已经不存在** ——
   `Engine/Classes/Components/SoundComponent.h` 整个文件都没了
   → `SoundComp->bLooping = true` 这种 UE4/UE5 早期写法直接 **C2065 未声明**
3. **循环播放的唯一可靠路径 = `USoundWave::bLooping`**
   （源码注释：If set, when played directly (not through a sound cue) the wave will be played looping）
   - `USoundBase::IsLooping()` 的基类实现是 `GetDuration() >= INDEFINITELY_LOOPING_DURATION`，
     普通 SoundWave 不满足 → 基类那个判断对我们要的场景没用
   - 打开后 `GetDuration()` 报 **10000.0s**（= `INDEFINITELY_LOOPING_DURATION` 哨兵值），
     **这不是 bug**，正是"无限循环"的标志，日志里看到别以为时长读错了
   - C++ 侧还兜底补一刀：`if (!Wave->bLooping) Wave->bLooping = true;`（只改内存，
     正式做法还是资产上勾好存盘）

## BOSS 破防锁死加固 + 顺带挖出"BOSS 走不到玩家面前"

### 1. 破防倒地期间的"一动不动"（用户："boss破防才倒地，倒地就不能移动"）

**审计结论：倒地只由破防触发。** 虚弱蒙太奇 + 跪地锁位都挂在 `bBrokenNow = ASC->HasMatching(State_Broken)`
（`BossCharacterBase.cpp` Tick 里的"破防（虚弱）表现"段），`State_Broken` 只在
`DemoAttributeSet` 里"韧性清零 / 架势打空 / 异常击破"三种判定时挂上。
受击硬直走的是另一个标签 `State_Hitstun`，死亡走 `State_Dead` + 独立的 `UpdateDeathFreeze`。

**但原来那套锁位不够硬。** 之前只做"每帧清速度 + 钉回锚点"，移动组件**内部仍然认为自己在下落**：
下一帧 `FindFloor` 判定悬空 → 又把胶囊体往下拽 → 视觉上原地抖动，看起来就是"跪着还在动"。

补上的最后一层（`UpdateBreakFreeze`）：
- 进入破防那一帧把 `MovementMode` 存进 `SavedBreakMoveMode`，然后 **`SetMovementMode(MOVE_None)`**
- 跪地期间每帧保证 `MOVE_None` + 速度清零 + 钉位置钉朝向
- 起身那一帧先钉回锚点再把 MovementMode **原样**还回去（不写死 Walking）
- ⚠ **MovementMode 只在进入破防的那一帧存**：压力测试会不停 `LaunchCharacter`，
  而 `Launch` 在 `MOVE_None` 下会把模式改成 `MOVE_Falling` —— 每帧都存的话，
  恢复时永远还原成 Falling，起身瞬间 BOSS 会突然往下掉

## 删掉「稳心（拼刀）」的整屏灰白闪

用户反馈："角色被攻击时稳心会有灰色的板出现，删掉"。

**根因**：`UCombatHUDWidget::HandleClashEvent`（稳心 = 拼刀事件 `Event_Clash` 的表现）里有一记整屏闪：
```cpp
FlashScreen(FLinearColor(0.92f, 0.95f, 1.f, 1.f), 0.30f, 0.28f);
```
`ScreenFlash` 是 `EnsureDefaultTree()` 建的一个**铺满全屏的 Image**，
所以它不是"闪过一道光"，而是**一整块半透明的矩形盖在屏幕上**。

**为什么只有它像"灰板"**：所有整屏闪里它是**唯一没有明确色相**的一层（0.92/0.95/1.0 ≈ 纯白），
28% 不透明度铺满全屏，在明亮的竞技场里读起来就是灰板。其余几层都带明确颜色：

| 事件 | 颜色 | 峰值不透明度 |
|---|---|---|
| 暴击 | (1, 0.88, 0.62) 暖金 | 0.16 |
| 普通弹反 | (0.45, 0.85, 1) 冷蓝 | 0.24 |
| 完美弹反 | (1, 0.82, 0.30) 金 | 0.45 |
| ~~稳心/拼刀~~ | ~~(0.92,0.95,1) 白~~ | **已删** |
| 完美闪避 | (0.78, 0.92, 1) 青白 | 0.32 |
| 普通闪避 | (0.50, 0.68, 0.95) 蓝 | 0.16 |

处理：只删这一层闪，**保留**镜头轻推（`ApplyCameraPunch(18, 0.24)`）和 `"稳 心 !"` 飘字 ——
用户抱怨的是"灰板"，不是稳心这个反馈本身。`run_build.py` exit 0；
无头回归（`demo.BossGuardTest 6`）HUD 正常、13 条格挡判定、无新增报错。

### 教训
- **整屏闪光 = 一个全屏 Image**，颜色里没有色相（≈纯白）时它读起来就是"灰板"而不是"闪光"。
  想做"中性提示"也要给一点色相（冷白/暖白），并且峰值不透明度别超过 ~0.2。

## 第二次修"稳心的灰板"—— 上一轮删错了对象，真根因是 ScreenFlash 没贴图

用户反馈"**还是有**被攻击时稳心会有灰色的板出现"。上一轮只删了拼刀那层白闪（0.28），没解决。

### 真根因：`ScreenFlash` 是**没有 brush 的 UImage** = 一块实心色板
`EnsureDefaultTree()` 里只做了：
```cpp
ScreenFlash = WidgetTree->ConstructWidget<UImage>(...);
ScreenFlash->SetColorAndOpacity(...);   // 只设了颜色，没设 brush
ScreenFlash->SetVisibility(Collapsed);  // 铺满全屏的 canvas slot
```
**没有设置任何 brush 的 UImage 画出来就是一块铺满屏幕的实心矩形** ——
每次 `FlashScreen()` 都是"盖一块半透明色板"，颜色只是 tint 到这块白板上。
**近白色 + 28%~45% 不透明度 = 灰板。**

### 用户看到的其实是"被攻击 → 完美弹反（= 稳心）"那两层
- 一次完美弹反会**同时**触发 `HandleParryEvent` 和 `HandlePerfectParryEvent`
  （代码注释写明"结构上它和 HandleParryEvent 会同时被触发"）
- → 冷蓝 0.24 **紧跟着**金闪 0.45（全场最亮的一层）连闪两下 = 一大片盖住视野的色板
- 拼刀那层（上一轮删掉的）并不是用户看到的那一块

### 本轮处理（两步，缺一不可）
1. **删掉"被攻击"路径上的全部整屏闪**：
   - 完美弹反金闪 `(1,0.82,0.30)/0.42s/0.45` ← 用户看到的那块
   - 普通弹反冷蓝闪 `(0.45,0.85,1)/0.26s/0.24`
   - 拼刀稳心白闪 `(0.92,0.95,1)/0.30s/0.28`（上一轮已删）
   - **保留**镜头冲击（普通弹反 16/0.22、完美弹反 32/0.36、稳心 18/0.24）+ 飘字 + 顿帧 + 火花
2. **给 ScreenFlash 补上径向渐变贴图**（治本）：`MakeRadialFlashTexture()` 运行时生成
   128×128、中心白四周透明（`pow(1-r,1.6)`）的 `UTexture2D`，`SetBrushFromTexture` 挂上。
   剩下的闪（暴击 0.16 / 完美闪避 0.32 / 普通闪避 0.16）从此是"画面中央泛一下光"。

编译 exit 0；无头回归：渐变贴图生成成功（无告警）、HUD 绑定正常、无新增报错。
**未在 PIE 里肉眼验收**（无头 -NullRHI 验不了 UI），需要用户重启编辑器后自己看一眼。

### 教训
- **UMG 里"Image 不设 brush" = 实心色板**，不是"什么都不画"。做全屏闪光/渐晕必须给贴图。
- 同一个交互事件可能同时绑**多个 Handler**（弹反 + 完美弹反），两屏闪会叠着闪 → 排查时先数调用点。
- `TBulkData` 在 UE5.7 是 `Lock(LockFlags)/Unlock()`，**没有** `LockBulkData/UnlockBulkData`（C2039）。
- 反馈层里"闪一下"要么**给径向渐变贴图 + 低不透明度**（像闪光），
  要么直接删掉、靠镜头冲击/飘字/顿帧表达 —— 纯色全屏矩形一定是"板"，不会有人觉得是闪光。

## 第三次"稳心的灰板"—— 真凶是**弹反扩散环那张几米大的平面**

前两轮都改错了（拼刀白闪 → 弹反/完美弹反屏闪），第三轮才找到真正会变成"板"的东西。

### 真凶：`ADemoImpactBurst` 的扩散环 = 一张被放到 **3.64m** 的 Plane
`RingMesh` 用的是引擎基础平面 `/Engine/BasicShapes/Plane.Plane`（100cm），
最终边长 = `Radius × RingEndScale(2.6) × 2`：
- 弹反/稳心：`Radius = ParrySparkRadius(70)` → **70 × 2.6 × 2 = 364cm**
- 生成点 = 两人之间的 parry point，**离镜头只有 1~2m**
- HDR 强度 `PeakIntensity(14) × 0.55 = 7.7`，加法混合 + Bloom
→ 一张 3.6m 的加法平面糊在镜头前，读出来就是"一块板"（用户在明亮的大理石场景里看到的是灰白色）。
`bUseFlash=false` 只关掉了中心那个**球**，**环一直开着** —— 这是前三轮都没注意到的盲点。

### 改法：给 `SpawnBurst` 加 `bUseRing` 参数，弹反 / 拼刀传 false
- 弹反、拼刀现在只剩：点光一闪 + 顿帧 + 镜头冲击 + 飘字（+ 伤害数字）
- 其它路径（BOSS 受击火花、格挡火花、弹丸命中）**保持原样**，地面冲击环还在

### ★★ 这次真正的拦路虎：**编辑器开着，DLL 被锁住**
`python Tools/run_build.py --manual` 的结果：
```
[manual] 编译完成：成功 5，失败 0
[manual] 开始链接 ...
link.exe rc=1104
LINK : fatal error LNK1104: 无法打开文件 K:\selfgame\demo\Binaries\Win64\UnrealEditor-demo.dll
```
`tasklist` 显示 **UnrealEditor.exe (4.2GB) + LiveCodingConsole.exe 都在跑** →
DLL 被进程占着，**链接这一步过不去，改动等于没生效**。

⚠⚠ 由此得出两条流程铁律：
1. **用户开着编辑器时，我编不出新 DLL**（`--manual` 也一样，rc=1104）。
   唯一出路：让用户**关掉编辑器**（我再编），或让用户在编辑器里按 **Ctrl+Alt+F11** 走 Live Coding。

### 教训
- **特效 actor 里"贴地扩散环"在近身距离会变成一堵墙**：几百厘米的平面在 1~2m 外 = 满屏。
  近身冲击类特效要么关掉环、要么把 `RingEndScale` 压到 1 以内。
- 排查"画面里有个板"要按**尺寸算一遍**：网格基准尺寸 × 缩放系数 × 生成点离镜头的距离。
- 改 C++ 前先 `tasklist` 看编辑器在不在，能省掉一轮"改了没生效"的空转。

## 屏幕左上角那堆黄字（VSM 非 Nanite 阴影溢出）—— 纯配置解决，不用编译

用户截图里屏幕顶部有两条黄色警告：
`[7/8]非Nanite标注工作队列溢出… 6 seconds ago. See /:Shadow/Virtual AllowScreenOverflowMessages`

**根因（读引擎源码确认）**：Fab 竞技场是**一个 57m×144m 的单体非 Nanite 网格**，
它的阴影铺满 Virtual Shadow Map 的页缓存 → `VirtualShadowMapCacheManager.cpp:990` 处
`if (GVSMAllowScreenOverflowMessages != 0) OutMessages.Add(Warning, …)` **主动往屏幕消息列表插警告**。
不是我们自己的日志。

**处理（`Config/DefaultEngine.ini`，两道保险）**：
```ini
[/Script/Engine.Engine]
bEnableOnScreenDebugMessages=False      ; 整个屏幕消息系统关掉（UnrealEngine.cpp:2213 在启动时读）
[SystemSettings]
r.Shadow.Virtual.AllowScreenOverflowMessages=0   ; 不再往上屏幕插这一条（治源）
```
- 当场生效的办法：控制台（~）输 **`DisableAllScreenMessages`**（别名 DisableScreenMessages）；
