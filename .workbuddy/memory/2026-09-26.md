## 锁定视角返工（DLL 14:50 / 1866240 字节）

用户反馈"贴身打时镜头疯狂晃动，还是没有锁定在 boss 模型身体中心"。两个症状同一个根源，
都是我这轮新加的**绕背预测**：

1. **外推写成了固定厘米数**（`Speed*0.12s`，上限 120cm）—— 违反项目铁律。
   贴身 D≈150 时 atan(120/150)≈39°，瞄准点被推出 BOSS 身体外面。
2. **硬阈值开关**（夹角 >60° 立刻全量生效）—— 夹角在阈值附近来回穿越，镜头反复跳。

**修法**（`FightPlayerCharacter.h/.cpp`）
- 外推改为按恒定角度：`min(Speed*LeadTime, DistToFocus*tan(LockOnPredictAngleDeg))`。
- 夹角改 smoothstep 渐变（StartAngle=50 → +Ramp 35），偏移量再 `VInterpTo` 逐帧平滑（新成员 `CurrentPredictOffset`）。
- **`LockOnPredictAngleDeg` 默认 0° = 关闭** → 瞄准点恒等于 BOSS 身体中心，绝对居中；要预判就调 2~4°。

**顺带自查出的第二个问题**：Turn In Place 死区 35° 太松 —— 锁定后角色最多偏 35° 不转身，
"锁定感"没了。收紧到 **5°**（死区只该滤亚度级噪声）。

**教训**：本项目"横向偏移必须按角度缩放、不能写死长度"这条铁律，我在两个不同的地方各踩了一次。
以后加任何相机偏移，先问"它随距离变化吗"，答案是"不随"就必须改成 `D*tan(角度)`。

## 锁定视角第二根因：CameraLag（待编译）

用户再次反馈"锁定疯狂抖动 + 没锁在 BOSS 身体中心"。关键事实：

- `bUseControllerRotationYaw = false` → 也不存在"相机→控制朝向→角色→相机"的反馈环，排除。

**真根因（高置信）**：`FightPlayerCharacter.cpp` 的 `UpdateLockOnCamera` 用**解析模型**解算朝向：
`相机 = 枢轴 + 朝向×臂长 + 朝向旋转后的 SocketOffset`，但弹簧臂开着 `bEnableCameraLag = true` ——
**真实相机位置滞后于解析模型** → "让 BOSS 居中"的解算前提不成立 → BOSS 偏离中心。
位置误差 e 的角误差 ≈ `atan(e / 距离)`：**贴得越近放大越狠** → 解释"贴身时疯狂晃"。
（代码注释自己写着"用解析模型避免受 CameraLag 影响"—— 但只有 lag 关掉时这个论证才成立，
 lag 开着时解析模型反而是错的。这是设计内部自相矛盾。）

**修法（源码已改，未编译）**：`UpdateLockOnCamera` 里按模式强制滞后开关——
锁定 → `bEnableCameraLag = false`；解锁 → 还原 `CachedDefaultCameraLag`（新增成员，BeginPlay 缓存）。
用 `!bCameraStateSavedByDisplacement` 让位给闪避的位移辅助（它本来就自己管滞后）。

### ★ 锁定抖动【真根因】找到了（19:10，待编译）

用户反馈"只有移动 / 出招时才抖"。诊断开关输出（读 `Saved/Logs/demo.log` 原始日志，不用截图 OCR）：
`lag=0`、`pred=0.0`、`focus` 恒定、`charYaw` 稳定 —— 全部排除。
决定性证据：**`des` 相对 `DirectAim` 的偏差从 -6° 一路漂到 +54°**，而安全闸只有 ±14°。

**根因：肩位补偿的缩放距离用错了。**
```cpp
ShoulderMag = min(|SocketOffset|, DistToFocus * tan(7°))   // DistToFocus = 枢轴→焦点
```
但补偿角 = `atan(偏移 / 【相机→焦点】距离)`，相机在枢轴后方 `ArmLen` 处，
所以相机到焦点 ≈ `DistToFocus − ArmLen`。

- 调参那会儿 D≈1500、臂长 480 → D−L≈1020，凑出 ≈7°，**被误当成对的**；
- 但**贴身**时 D 掉到 346~605，臂长还是 480 → 相机几乎贴到 BOSS 脸上，
  `atan(127.5/(500−480))` → **爆炸**，随即被 ±14° 安全闸夹死：
  BOSS 被顶出画面中心（"没锁定在身体中心"），移动时 D 一变角度剧烈跳（"只有移动时才抖"）。
- 同时固定臂长 480 > 近距离的 D → 相机被弹簧臂顶到 BOSS **身后/体内**，
  解算模型与实际相机位置彻底脱节（叠加 `bDoCollisionTest` 回缩更乱）。

**修法（源码已改，未编译）**
1. **肩位按 (D − ArmLen) 缩放**：`CamToFocus = max(DistToFocus - ArmLen, 50)`，
   `ShoulderMag = min(|SocketOffset|, CamToFocus*tan(7°))` → 任何距离补偿角恒 7°，安全闸不再被夹。
   （`ArmLen` 上移到 ShoulderMag 之前计算。）
2. **臂长自适应**：`DesiredArm = clamp(D - LockOnCameraStandoff(420), LockOnArmMin(200), LockOnArmLength(480))`，
   相机恒定停在焦点前方固定距离 → 模型永远成立，也不再穿进 BOSS。

**教训（第三次栽在"距离/长度写死"上）**：
凡是"按角度缩放"的公式，分母必须用【真正决定该角度的那个距离】。
这里的角度由相机→焦点的距离决定，写枢轴→焦点就错了 —— 而且**在调参距离上看起来是对的**，
这类 bug 只有换距离才暴露。判据：`atan(偏移 / X)` 里的 X 必须是"偏移所在的那个直角三角形"的邻边。

**追加（19:17 用户反馈"贴太近视角乱动 + 模型重叠"→ 印证根因）**
- 自适应臂长再叠一层下限：`ArmFloor = min(LockOnArmMin, DistForArm * 0.5)`，
  `DesiredArm = clamp(D - Standoff, ArmFloor, LockOnArmLength)`。
  **臂长 ≤ D/2 ⇒ 相机永远在目标前面**（否则下限会把相机又顶到 BOSS 身后）。
- "模型重叠"另有一源：`BossCharacterBase` 里 `MoveComp->MaxDepenetrationWithPawn = 4.f`
  （为了"温柔分开"压得很低）→ 玩家可挤进 BOSS 胶囊。想减少可见穿模就适当调大（3~10 之间权衡）。
- ✅ **已编译**（19:20:34，DLL 1,868,800 → **1,870,336** 字节，走 ManualBuild 回退通道，
  6 个 TU 重编 + 12 个 obj 重链）。验收待用户实测。

  `build_log.txt` 明确写 `Unable to build while Live Coding is active`）。

## ★ "锁定没锁在 BOSS 身体中心"【真根因】：HUD 投影没除 DPI 缩放（DLL 21:11:59）

用户截图显示：锁定准星**飘在 BOSS 左上方半空**，而 BOSS 本体其实**基本在画面中心**
（相机是对的！）。所以这是 **HUD 控件定位**问题，不是相机问题。

**根因**：
```cpp
PC->ProjectWorldLocationToScreen(..., ScreenPos, false);   // 返回【视口像素】
MarkerSlot->SetPosition(ScreenPos);                        // 槽位要【控件本地单位】
```
两者差一个 DPI / 视口缩放。本项目 **没配 DPI 曲线** → 走 UE 默认 `ShortestSide`，
1080 高时缩放 ≈ **0.757** → 位置被整体乘 0.757 = **朝左上拽**（实测准星在 BOSS 的 ~0.73~0.82 倍位置，吻合）。

**修法**：除以 `UWidgetLayoutLibrary::GetViewportScale(this)`（=1 时为 no-op，安全）。
- `UI/CombatHUDWidget.cpp::SyncLockOnMarker`
- `UI/DemoDamageNumberLayer.cpp`（**飘字同一个 bug**：`CanvasSlot->SetPosition(ScreenPosition)` 也没除）

**教训**：UMG 里凡是用 `ProjectWorldLocationToScreen` 定位，必须除 `GetViewportScale`。
判据：投影是"屏幕像素"空间，CanvasSlot 是"控件本地单元"空间，两者之间永远隔着一个 DPI 缩放。
（本日第三次"空间/距离用错"的同类 bug —— 前两次是相机偏移与肩位补偿。）

**顺带**：VS 报"无法启动类库项目"的原因查清了 —— **VS 大版本升级（.vs/demo/v17 → v18）**，
启动项目设置存在版本专属的 `.suo` 里，升级后丢失 → 回退到 `.sln` 第一个真实工程
= `demoModuleRules`（C# 类库）。修法：右键 `demo` 设为启动项目，或直接双击 `.uproject`。

## 锁定攻击时镜头乱摇 + BOSS 攻击动画不播（源码已改，待编译）

用户复现两个老问题：① 角色攻击 BOSS 时锁定镜头疯狂乱摇；② BOSS 攻击动作根本不播。

### ① 镜头乱摇根因（新增，非相机解算）
`LockOnComponent::TickComponent` 锁定期间**每帧把玩家身体 `SetActorRotation` 拧向 BOSS**。
出招时招式自带**根运动（位移+朝向）**，两者打架：根位移把胶囊推开 → 朝向角变 → 下一帧再拧 →
弹簧臂挂在这个会甩动的身体上 → 相机甩动。玩家攻击 ability 挂 `State_Attacking`（PlayerAbilities.cpp:129/674）。
**修法**：`TickComponent` 里 `OwnerASC->HasMatchingGameplayTag(DemoTag::State_Attacking)` 为真时直接 return，
出招期间不强行拧身体（动作游戏通行：攻击起手即锁朝向，交给招式控面）。需 `#include "Core/DemoGameplayTags.h"`。
（之前那几轮相机解算本身已是对的：`bEnableCameraLag=false`、臂长自适应、`−ArmLen` 符号、肩位 (D−L) 缩放、DPI 除缩放。）

### ② BOSS 攻击不播根因（单节点模式没有 Slot 节点）
`SetupBossAnimation` 之前强制 `SetAnimationMode(AnimationSingleNode)` + `PlayAnimation(Idle序列)`。
查证引擎源码：`UAnimSingleNodeInstance` **只在 `SetAnimationAsset` 时注册该资产自带的 Slot**；
Idle 是**序列、无 Slot 轨道** → 单节点实例里**一个 Slot 节点都没有**。
而 BOSS 攻击蒙太奇（AnimMontageFactory 默认）全挂在 `DefaultSlot` → `Montage_Play` 找不到对应 Slot → 静默失败。
（玩家的攻击能动，正是因为玩家有真 ABP 带 `DefaultSlot` 节点。）
**修法**：`BossCharacterBase` 新增 `TSoftClassPtr<UAnimInstance> BossAnimBlueprint` +
`bool bUsesBossAnimBP`。`SetupBossAnimation` 优先 `LoadSynchronous`/按约定路径
`/Game/Boss/Animation/ABP_Boss.ABP_Boss_C` 加载，**`SetAnimInstanceClass` 切到 ABP_Boss**；
没建 ABP 时退回原单节点待机兜底（不回归，但攻击仍不播，提示用户去建）。
`UpdateBossLocomotion` 切到 ABP 后直接 return（Idle/Jog 交给 ABP 自己按速度混合，
否则 C++ 再 `PlayAnimation` 会把 ABP 打回单节点丢动画）。死亡仍用 `PlayAnimation(DeathSequence)` 冻结，无碍。

### ⚠ 必须由用户在编辑器手工建 ABP_Boss（Python 造不了 AnimGraph 节点）
Content Browser → Animation → AnimBlueprint，命名 `ABP_Boss`，Parent=`AnimInstance`，
**Skeleton 必须 = Khaimera_Skeleton**（不一致蒙太奇全播不了）。AnimGraph：
`Sequence Player(Idle_Relaxed_A, Loop)` + `Sequence Player(Jog_Fwd, Loop)` →
`Blend Poses by bool(bIsMoving)` → `Slot 'DefaultSlot'` → Output Pose。
EventGraph：`Event Blueprint Update Animation` → `TryGetPawnOwner`→`GetVelocity`→`Size2D`>阈值→`bIsMoving`。
（保险：打开任一 `Boss_*_Montage` 看 Slot 轨道名，ABP 的 Slot 节点名必须一致；大概率是 `DefaultSlot`。）
编译保存即可，C++ 会自动加载（也可在 BP_Boss 的 BossCharacterBase 默认里把 `BossAnimBlueprint` 指过去）。
