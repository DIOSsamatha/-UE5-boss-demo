# 设计主张：反馈驱动的博弈型 BOSS（Demo · UE 5.7 GAS）

> 这是一份**设计哲学 + 工程落地**文档，面向求职展示：它解释"为什么这么设计"、
> 每一处机制背后的根因假设、以及系统之间的耦合关系。具体数值与文件锚点以
> `Docs/FeedbackChainP1.md`（逐环实现记录）和 `Core/DemoCombatTuning.h` 为准。
>
> 项目：斜俯视 2.5D 动作玩法，单 BOSS 战。技术栈：Unreal Engine 5.7.4 + C++ + Gameplay Ability System。

---

## 0. 一句话主张

> **BOSS 不是一个血条，而是一个需要被"读"的对象。**
> 玩家的每一刀都必须产生**可见、可归因、可积累**的反馈；而 BOSS 的每一段"正在做事"的时间，
> 都必须是玩家能识别出来的**输出窗口**。反馈链的稀缺性，才是战斗张力本身。

这条主张贯穿了下面的每一个决策。下面把它拆成五条可执行的设计原则。

---

## 1. 设计原则

### 原则一：反馈必须四通（视觉 · UI · 听觉 · 数值），且能互相印证
玩家打的时候视线在 BOSS 身上，看 HUD 是低效的；转头看别处时材质又不生效。
所以**任何关键状态都不允许只有一条通道**：
- 失衡 UNSTABLE = 绿轮廓（材质）+ 绿槽（UI）+ `UNSTABLE` 绿标签（UI），三者**同一帧**发生。
- 举盾 GUARD = 冷蓝描边（材质）+ 护体光（光）+ 撞击音（听觉）。
- 受击 = 白光脉冲（材质）+ 火花（特效）+ 伤害数字（数值）。

如果只给一条通道，玩家会把"格挡掉的 25% 伤害"误读成"BOSS 血厚 / 我打不动"，
从而产生"这游戏打不动"的挫败感 —— 这是纯信息缺失导致的误判，不是难度问题。

### 原则二：读招优先于堆数值
BOSS 的招式伤害**全部为 0 配置、招式表数字 = 实际伤害**（攻防双方攻防力为 0）。
我们刻意不靠"数值碾压"制造难度，而是靠**读招窗口**：
- BOSS 起手（Telegraph）→ 出招（Attack）→ 后摇（Recover）三段分明；
- 起手期有**快闪红光**预警（和举盾的极慢蓝呼吸严格区分，靠频率而非只靠颜色）；
- 后摇是给玩家的免费输出窗口，霸体只在"已 committing 的招式"期间存在，
  普通攻击点不掉，保留 BOSS 的压迫感。

### 原则三：三条资源条职责硬分离，绝不混用
| 资源 | 语义 | 谁消耗它 | 满/空触发 |
|---|---|---|---|
| **韧性 Poise** | "被打多久会进硬直" | 挨打 | 归零 → 破防虚弱（处决窗口） |
| **异常 Anomaly** | "我打出多少进展"（双槽：冲击/元素） | 输出 | 冲击满 → 失衡；元素满且已失衡 → 击破 |
| **架势 Posture** | "防御还能撑多久"（盾的耐久） | 防御 | 归零 → 破防（盾被打破，吃 60% 伤害） |

这三条是**正交**的：韧性是"被打的代价"，异常是"输出的进度"，架势是"防御的耐久"。
新增任何资源前，先确认它补的是反馈链上的哪一个洞 —— 否则就是又一条没人看得懂的条。

### 原则四：防御三手段必须相互约束
挡 / 弹 / 闪单独存在都会退化成最优解。靠**架势条**把它们绑在一起：
- 一直挡 → 架势见底 → 被破防；
- 弹反 / 闪避成功 → 回架势（稳心），于是"借来的防御必须还回去"。
- 拼刀（稳心）回报 **低于** 完美闪避和完美弹反，避免玩家去赌对撞而不是读招。

### 原则五：BOSS 默认会挡 —— 否则反馈链塌一半
没有默认格挡，玩家随时能把伤害打进去，"击破窗口"和"后摇窗口"就都没有稀缺性。
有了默认格挡，BOSS 才从沙袋变成博弈对象；而格挡又必须用**反制**和**可见姿态**补足，
否则玩家的最优解仍是"贴脸砍到它抬手"。

## 2. 核心反馈链（系统的脊柱）

```
   玩家输出 ──► 命中 BOSS ──► 异常积累(冲击/元素槽)
        │                          │
        │                          ├─ 冲击满 ─► 失衡 UNSTABLE(受伤×1.25, 6s)
        │                          │                │
        │                          │                └─ 元素满 ─► 击破 BROKEN(虚弱 3.5s, 完全不挡)
        │                          │
        └─ 抓后摇/出招窗口 ──► 全额伤害(不挡的时段)
        └─ 打空架势 ──► 破防(和玩家同一套规则, 对称)

   反过来：BOSS 默认举盾(中立态) ──► 伤害×0.25 + 冷蓝火花
                                     └─ 连续被挡 3 次 ──► 反制还手
```

**关键设计点**：这条链里**没有任何一个节点是"白打"**。
- 你砍它 → 异常槽在涨（可见进度）；
- 你抓后摇 → 全额伤害（读招回报）；
- 你打空它架势 → 破防（对称规则）；
- 它挡你 → 你被压到 1/4 输出，逼你去用上面三种手段。

于是"只砍不弹"推不动第二条槽，"只弹不砍"推不动第一条 —— **读招与输出被强制耦合**。

## 3. 状态信号规范（可读性底色）

| 状态 | 颜色 | 节奏 | 触发 |
|---|---|---|---|
| 起手预警 Telegraph | 🔴 红 | **快闪** | BOSS 要出招了 |
| 受击 Hit | ⚪ 白 | 一次脉冲 | 任何命中 |
| 失衡 Unstable | 🟢 绿 | 慢呼吸 1.6Hz | 冲击槽满 |
| 举盾 Guard | 🔵 冷蓝 | **极慢呼吸 0.7Hz** | 中立状态 |

> **节奏本身就是语义**。举盾如果闪快了，会被玩家误读成"它要出招了"。
> 颜色对了但频率错了，信号就错了。这条规范写在长期记忆里，任何新表现加进来前先查这张表。
> 每条状态至少要有【材质/光 + UI】两条通道 —— 只做一条，总有一半时间玩家看不见。

## 4. BOSS 招式表与阶段

| 招式 | 类型 | 设计意图 |
|---|---|---|
| 近战连段 ×6 | `MeleeSlash` | 覆盖面/突进挑斩/重砸（重砸慢起手 = 大硬直窗口） |
| 远程弹幕 | `RangedBarrage` | 施法抬手 + 弹道（取不到资源优雅降级） |
| 突进斩 | `ChargeSlash` | 蓄势(可弹反) → 贴地匀速突进 → 扇形收尾；二阶段缩放距离/半径 |
| 大招 | `Ultimate` | 蓄力循环 → 收力，二阶段才解锁 |

- **阶段演进**：阶段 1（挥砍/弹幕/突进斩）→ 阶段 2（同一批招式自动强化 + 大招解锁），
  由 `UBossBrainComponent` 的状态机驱动；氛围/AI 参数随阶段切换。
- **贴地约束**：BOSS 用 `SetPlaneConstraintOrigin(当前位置)` 而非世界原点，否则招式结束会"弹回飞天"。

## 5. 伤害门控与唯一入口

所有伤害走**唯一入口** `UDemoAbilitySystemLibrary::ApplyHit` → `UDemoDamageEffect`
→ `UDemoDamageExecution` → `UDemoAttributeSet::PostGameplayEffectExecute`：
1. 阵营过滤 → 2. 无敌帧 → 3. 弹反 → 4. 格挡 → 5. 破防暴击。

- **门控**：`BaseDamage>0 || AttackPower>0` 才结算，否则 `FinalDamage=0`（HP 不变但命中事件照发，
  表现为"打中却不掉血" —— 这是预期，不是 bug）。
- **真实伤害只在 `PostGameplayEffectExecute` 的 `Magnitude` 拿**，不要在结算外另算一份。
- **状态跃迁的套路**：属性侧只广播，角色侧 `HandleXxx()` 统一做"挂 tag + 硬直 +
  取消冲突技能 + 起恢复定时器"；清空资源用 `SetNumericAttributeBase`，**不要**再发 GE 清零
  （会再触发一次"打满/打空"判定 → 自激）。

## 6. 工程纪律（让设计可维护）

| 纪律 | 落地 |
|---|---|
| 数值只落在三处 | `DemoAttributeSet` / `DemoDamageExecution` / `DemoCombatTuning` |
| 无 `Tick` 内 `GetAllActorsOfClass` | 失衡/举盾视觉是 tag 查询（O(1)），无索敌 |
| 事件驱动而非轮询 | 伤害/破防/格挡全部走 GAS 事件与 `OnXxx` 委托 |
| 资产按约定路径兜底 | 蒙太奇 `Tools/SetupBossMontages.py`、特效 `Tools/SetupBossVFX.py` 脚本生成，C++ 按路径加载，**不依赖手拖蓝图** |
| UPROPERTY 完整 | 动态材质实例/光组件都挂 `UPROPERTY()`，防 GC 误收 |
| 防御侧不依赖 Boss 模块 | 格挡分支在伤害库里，小怪也能复用同套规则 |

## 7. 关键数值速查（详见 `DemoCombatTuning.h`）

- 血量：玩家 2000 / BOSS 10000；双方攻防 0（招式表数字 = 实伤）。
- 格挡伤害 ×0.25；架势被打空瞬间吃 60%（而非 25%），破防窗口内受伤 ×1.5。
- 异常双槽容量 100/100：普攻连段冲击 +7；技能 冲击 +10 / 元素 +18；普通弹反 元素 +22；完美弹反 元素 +30。
- 失衡持续 6s、受伤 ×1.25；击破虚弱 3.5s。
- 架势：玩家上限 100，BOSS 上限 180（和玩家一样会太脆）；格挡扣 `8 + 伤害×0.25`；
  完美闪避回 +25，完美弹反回 +18，拼刀回 +15，被打空后 1s 起身回半槽。
- 拼刀：判定窗 0.15s、冷却 0.6s、定帧 0.10s@0.10。
- BOSS 反制：连续被挡 3 次 → 强制还手一次。

## 9. 一句话复盘（给面试官）

> 我没有用"加血加伤"来做难度，而是搭了一条**玩家每刀都能读出进展、BOSS 每段动作都是窗口**
> 的反馈链，再用三条正交资源（韧性/异常/架势）把"输出—防御—破防"锁成一个闭环。
> 工程上所有数值集中、所有伤害走唯一入口、所有资产脚本化生成 —— 设计意图和代码结构是同一张图。
